# Witch Pack Design

**Date:** 2026-09-24
**Pack name:** `witch`
**Branch:** feat/ceap-animation-pack

---

## Concept

A pixel-art witch seated at a cluttered wooden desk: pointed hat, purple robes, a glowing
grimoire that is also her laptop. Stone dungeon setting lit by warm torchlight and purple
arcane light. Warm and expressive — the hat and runes carry a lot of visual weight that
makes reactions read clearly at small sizes.

**CEAP features exercised:**
- Multiple variants on `typing` (focused vs frantic) — variant selection with 2 candidates
- Split-files authoring (every category is its own file)
- Animated border with `margin`
- All 6 categories
- `dot_colors`, `corner_radius`, `render_density`
- `bg` layer

---

## Atlas Spec

- **Per-frame size:** 400×400 px native
- **`render_density`:** 2.0 → 200 CSS px on-screen (retina: 400 native px fills 400 physical px at @2x)
- **`corner_radius`:** 40 native px → 20 CSS px — noticeably rounded corners
- **Authoring style:** Split files — one strip per category, no shared atlas

Each file is a horizontal strip: `N frames × 400` px wide, 400 px tall.

| File | Category / Role | Frames | FPS | Loop | Strip size |
|---|---|---|---|---|---|
| `sleeping.png` | sleeping | 6 | 3 | yes | 2400×400 |
| `waking.png` | waking | 6 | 6 | no (loops: 1) | 2400×400 |
| `typing-focused.png` | typing variant 1 | 6 | 8 | yes | 2400×400 |
| `typing-frantic.png` | typing variant 2 | 8 | 14 | yes | 3200×400 |
| `alarmed.png` | alarmed | 6 | 10 | no | 2400×400 |
| `celebrate.png` | celebrate | 8 | 10 | no | 3200×400 |
| `annoyed.png` | annoyed | 6 | 8 | no | 2400×400 |
| `borders.png` | animated border | 8 | 10 | yes | 3200×400 |
| `bg.png` | background | 1 | — | — | 400×400 |
| `dock-icon.png` | dock icon source | — | — | — | 1024×1024 |

`typing` has **2 variants**: the player picks randomly between them with no-immediate-repeat
on every session transition into `typing`.

`celebrate` and `alarmed` are **8 and 6 frames** respectively — different counts from each
other and from the steady states, exercising per-file frame independence.

**Border:** same 400×400 px per frame as the sprite, rendered at the same density (200 CSS px).
Overlaid on top of the sprite with a transparent center. `margin` in the manifest is the artist's
estimate of the opaque ring half-width in native px — tells the window how much to grow so the
border art isn't clipped. Exact value depends on how thick the ring is and how much sprite overlap
is acceptable. The witch border uses a ~20 native px ring → `margin: { x: 20, y: 20 }`.

## Notes

- **Retina:** 400px native / density 2.0 = 200 CSS px on-screen. At @2x Retina, 200 CSS px
  = 400 physical pixels — the art maps 1:1 to physical pixels with no upscaling blur.
- **Border:** same 400×400 px as the sprite frame, overlaid on top. The transparent center
  lets the sprite show through. `margin: { x: 20, y: 20 }` is an estimate of the ring
  half-width in native px — the window grows by 20/2.0 = 10 CSS px on each side so the
  ring edge isn't clipped. Adjust in the manifest after seeing the actual art.
- **corner_radius:** 40 native px / 2.0 = 20 CSS px — clearly rounded but not capsule-shaped.
- `typing-frantic.png` is 8 frames (not 6) — exercises different frame counts between variants.
- Run `node scripts/generate-dock-icons.js` after placing `dock-icon.png`.
